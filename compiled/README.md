# compiled

Folded variants of the pipeline canon, compressed through the llm-script
register for a model audience.

*Provenance: folded from `pipeline/` against canon V3.3, August 2026, by the
library orchestrator. No human pass. Not eval-certified: see below.*

## What these are

The llm-script register flips the audience. A craft file in `pipeline/` is
written for a person who might also hand it to a model. A file here is written
for a model, so the optimization target changes from reading as a human hand to
operational strength per token. Orwell's rule three becomes the dominant pass,
McDonald sharpens to one job per file, and Forsyth stands down entirely, because
figures spend tokens on effects a model does not need.

Every fold is monotone: removal and restatement only, no new claims. Every rule
survives with its trigger conditions and its decision-rights language. Every
number survives exactly, including budgets, targets, standard deviations, and
hallmark IDs. File names are unchanged so cross-references resolve and any
degradation localizes to one file.

**The source files are master.** The fold is lossy and one-directional. Where a
folded file and its source disagree, the source governs, and the fold is the
thing that is wrong.

## What is folded, and what is not

All seventeen pipeline files are folded. The mapping is one to one and names
are unchanged, so a cross-reference in a folded file resolves against either
directory and any degradation localizes to the file it happened in.

The unfolded eleven are not missing anything. They are simply not compressed, and
a model given the `pipeline/` version of any of them gets the full file. Folding
the rest is work anyone can pick up: the rules are in `register-profiles.md`
under the llm-script register, and they are specific enough to follow.

## Not certified

An earlier fold of the July 2026 canon was measured against the library's
behavioral evaluation kit and certified at six of six cells, with four improving
and none degrading. **These folds carry no such backing.** They were produced
against V3.3 canon and have not been run through the kit.

That matters because the fold's whole claim is semantic parity: the compressed
file should behave as the source behaves. Parity is a measured property, not a
judged one, and nobody has measured these. Use them where the token saving is
worth an unverified variant, and use `pipeline/` where it is not.

The measurement is not expensive and the method is documented in
`register-profiles.md` under the llm-script register: ordinal no-worse per cell
against the source, no new failure modes at equal score, no offsetting.

## Compression achieved

The folds run between 60 and 97 percent of their source word counts and
aggregate to 79 percent. The July compile reported 71 percent library-wide.

That number is an aggregate and not a per-file target. A dense file resists compression because there is little to remove, and the
extremes here are both correct. `goldberg-first-thoughts.md` folds to 60 percent
because it is discursive. `register-profiles.md` folds to 97 percent because it
is six budget tables, and the tables are reproduced verbatim: the invariant that
all numbers survive exactly outranks any ratio. `lamplighter-protocol.md` holds
at 86 percent because its worked example is a lipogram and an acrostic, where a
dropped word breaks a constraint the piece exists to demonstrate.

The rule is Orwell's rule three, every word that can go goes, and the ratio is
the result rather than the objective.
